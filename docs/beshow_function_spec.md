# 비었쇼(Be:show) 기능 명세서

## 1. 기능 범위
1. 보충 필요 SKU 식별
2. 발주 필요 SKU 식별
3. 상태 판정(`정상/보충 필요/확인 필요/발주 필요`)
4. 선반 이미지+탐지 결과 연계
5. 알림 패널(SCR-opt) 제공
6. 작업 완료 처리(보충/발주)

---

## 2. 상태 판정 로직

입력:
1. slot 단위 CV 탐지 결과
2. 기준 진열(planogram)
3. 창고 재고/ROP

판정:
1. `정상`: 기준 위배 없음
2. `보충 필요`: 진열 부족 + 창고 보충 재고 존재
3. `확인 필요`: 오진열/저신뢰/판단 애매
4. `발주 필요`: 보충 필요 조건 + 창고 재고 부족(ROP 이하 또는 0)

노출 정책:
1. SCR-1 노출: `정상/보충 필요/확인 필요`
2. SCR-2 노출: `발주 필요`
3. 동시 조건 SKU(`보충 필요 + 발주 필요`)는 SCR-2 우선 노출

---

## 3. 핵심 기능

## 3.1 CV/탐지
1. SKU 객체 탐지
2. bbox -> slot 매핑
3. 결손/오진열/저신뢰 후보 계산
4. 매대 SKU 0개 이벤트 생성

## 3.2 리스트 생성
1. SCR-1 보충 필요 리스트 생성
2. SCR-2 발주 필요 리스트 생성
3. 리스트는 SKU 중복 제거(한 SKU당 1행)
4. 우선순위/상태/시간 기준 정렬

## 3.3 상세 조회
1. SCR-1.1 모달 상세 데이터 조회
2. SCR-2.1 모달 상세 데이터 조회

## 3.4 처리 액션
1. 보충 완료 처리
2. 발주 완료 처리
3. 처리 결과 이벤트 로그 기록

## 3.5 알림
1. 알림 목록 조회
2. 알림 클릭 시 대상 SKU 포커스 이동
3. 미확인 알림 카운트 갱신

---

## 4. 화면별 기능 매핑
1. `SCR-1` 보충 필요 리스트 + 선반 이미지 + SKU 선택
2. `SCR-1.1` 보충/확인 필요 SKU 상세 모달
3. `SCR-2` 발주 필요 리스트
4. `SCR-2.1` 발주 필요 SKU 상세 모달
5. `SCR-opt` 우측 슬라이드 알림 패널

---

## 5. 데이터/기술 요구사항
1. 선반 이미지: S3 key + Presigned URL
2. 상태/이력: 이벤트 테이블 기반
3. 리스트 응답: 화면 렌더 즉시 가능한 view-model 제공
4. 중복 SKU 제거는 API 응답 레벨에서 보장
