# 비었쇼(Be:show) 화면 명세서 (Screen Spec)

## 1. 목적과 범위
1. 본 문서는 프로토타입(`SCR-1`, `SCR-1.1`, `SCR-2`, `SCR-2.1`, `SCR-opt`) 기준으로 프론트엔드/백엔드 구현에 필요한 화면 요구사항을 정의한다.
2. MVP 화면 범위는 `SCR-1 보충 필요 리스트`, `SCR-2 발주 필요 리스트`, `SCR-opt 알림 패널`이다.
3. 본 문서는 태블릿 웹(16:10) 기준이며, 디자인 시안과 동일한 탑 네비게이션 + 콘텐츠 패널 구조를 따른다.

---

## 2. 정보 구조 (IA)
1. `SCR-1 보충 필요 리스트` (기본 진입 화면)
2. `SCR-2 발주 필요 리스트`
3. `SCR-opt 알림 패널` (전역 오버레이)

전역 공통 요소:
1. 좌상단 로고(아이콘 + 워드마크)
2. 상단 탭 내비게이션 2개
3. 점포 선택 드롭다운
4. 우상단 유틸 아이콘(테마/갱신/알림)

---

## 3. 공통 UI 규격

## 3.1 디바이스/레이아웃
1. 타깃: Tablet Web
2. 기준 화면비: 16:10
3. 기준 해상도: 1280x800
4. 최소 폭: 1024px
5. 콘텐츠 최대 폭: 1440px

## 3.2 공통 컴포넌트 규칙
1. 리스트는 페이지 전체 스크롤이 아닌 `리스트 영역 내부 스크롤`을 사용한다.
2. 동일 리스트 내 `동일 SKU 중복 행 금지`를 기본 규칙으로 한다.
3. 상태 배지는 텍스트+색상 동시 표기한다.
4. 시간 표기는 `YYYY.MM.DD HH:mm` 포맷을 사용한다.
5. 모달 오픈 시 배경에 스크림(반투명 오버레이)을 적용한다.

## 3.3 상태값 표준
1. `정상`
2. `보충 필요`
3. `확인 필요`
4. `발주 필요`

노출 정책:
1. SCR-1은 `정상/보충 필요/확인 필요` 중심으로 노출한다.
2. SCR-2는 `발주 필요`만 노출한다.
3. `보충 필요`와 `발주 필요` 동시 조건 SKU는 SCR-2 우선 노출 대상으로 분류한다.

---

## 4. SCR-1 보충 필요 리스트

## 4.1 화면 목적
1. 직원이 매대 보충 대상과 위치를 빠르게 확인한다.
2. 매대 이미지 기반으로 현재 상태를 직관적으로 확인한다.
3. 선택 SKU 상세를 모달로 확인하고 보충 작업으로 연결한다.

## 4.2 화면 구성
1. 상단 탭: `보충 필요 리스트` 활성
2. Overview 카드 3종
  - 정상 항목 수
  - 보충 필요 항목 수
  - 확인 필요 항목 수
3. Monitoring 섹션
  - 선반 선택 탭(예: 선반 A, 선반 B)
  - 선택 선반 이미지(탐지 오버레이 포함)
4. 작업 필요 리스트 테이블
  - 내부 스크롤
  - 컬럼: 작업 우선순위, 상품명, 상품 상태, 창고 재고, 위치, 탐지 시각

## 4.3 선반 이미지/탐지 영역
1. 선반 이미지에 결손/선택 객체 bbox를 오버레이한다.
2. 사용자가 선반 이미지의 객체를 클릭하면 해당 SKU가 리스트에서 하이라이트된다.
3. 사용자가 리스트 행을 클릭하면 이미지에서 해당 SKU bbox를 강조한다.

## 4.4 리스트 규칙
1. 한 행은 한 SKU를 의미한다.
2. 동일 SKU는 중복 생성하지 않는다.
3. 기본 정렬은 우선순위 오름차순(1이 최우선)이다.
4. 페이지 내 리스트 높이는 고정하고, 초과 데이터는 내부 스크롤로 처리한다.

## 4.5 SCR-1.1 SKU 상세 모달

모달 트리거:
1. SCR-1 리스트 행 클릭
2. SCR-1 이미지 객체 클릭

모달 구성:
1. 헤더
  - 상품 이미지(썸네일)
  - 상품명
  - SKU ID
  - 현재 상태 배지
2. 본문 정보
  - 탐지 시각
  - 창고 재고
  - 탐지 수량
  - 탐지 confidence
  - 진열 위치(예: 선반 A 3-3)
3. 하단 액션
  - `닫기`
  - `보충 완료 처리` (권한 허용 시)

모달 동작:
1. 스크림 클릭 또는 ESC로 닫힘
2. 보충 완료 처리 시 상태 재계산 요청 후 리스트/카드 즉시 갱신

---

## 5. SCR-2 발주 필요 리스트

## 5.1 화면 목적
1. 발주 필요 SKU를 별도 화면에서 집중 확인한다.
2. 발주 처리 전 검토 정보(재고/근거/위치)를 모달에서 확인한다.

## 5.2 화면 구성 (모달 오픈 전)
1. 상단 탭: `발주 필요 리스트` 활성
2. 요약 카드
  - 발주 필요 SKU
  - 전량 소진 SKU
  - 카테고리 분포
3. 발주 필요 리스트 테이블
  - 내부 스크롤
  - 컬럼: SKU ID, 상품명, 상태 전환 시각, 창고 재고, 진열 위치, 발주 완료 처리(체크)
4. 검색/필터
  - 텍스트 검색
  - 카테고리 선택
  - Reset
  - 업데이트 시간 표시

리스트 규칙:
1. 한 행은 한 SKU를 의미한다.
2. 동일 SKU 중복 금지
3. 발주 완료 체크는 행 단위 상태값으로 저장한다.

## 5.3 SCR-2.1 SKU 상세 모달

모달 트리거:
1. SCR-2 리스트 행 클릭

모달 구성:
1. 헤더
  - 상품 이미지(썸네일)
  - 상품명
  - SKU ID
  - 현재 상태(`발주 필요`)
2. 본문(요약 메트릭)
  - 상태 전환 시각
  - 창고 재고
  - 탐지 confidence
  - 진열 위치
  - 예상 리드타임(일)
  - 발주 필요 근거(예: ROP 도달, 전량 소진)
3. 하단 액션
  - `닫기`
  - `발주 완료 처리`

모달 동작:
1. 발주 완료 처리 시 해당 SKU는 SCR-2 리스트 기본 노출 대상에서 제외 가능(필터에 따라 표시)
2. 처리 이력은 이벤트 로그 테이블에 기록한다.

## 6. SCR-opt 알림 패널

## 6.1 화면 목적
1. 실시간 이벤트를 화면 이탈 없이 확인한다.
2. 알림에서 해당 SKU 상세로 빠르게 이동한다.

## 6.2 오픈 방식
1. 우상단 벨 아이콘 클릭 시 우측 슬라이드 패널 오픈
2. 패널 너비: 280~360px
3. 배경 화면은 유지하되 우측 패널이 오버레이된다.

## 6.3 패널 구성
1. 헤더: `알림`, 닫기 버튼
2. 알림 리스트(최신순)
3. 알림 카드 항목
  - 알림 제목 (예: 매대상 재고 전부 소진)
  - 위치 정보 (예: 선반 B 3-2)
  - 상품명
  - 발생 시각

## 6.4 인터랙션
1. 알림 카드 클릭 시 관련 화면으로 이동
  - 보충/확인 필요: SCR-1 해당 SKU 포커스
  - 발주 필요: SCR-2 해당 SKU 포커스
2. 패널 바깥 클릭 또는 닫기 버튼으로 종료

---

## 7. 화면 전환 플로우
1. 상단 탭 클릭으로 `SCR-1 <-> SCR-2` 전환
2. SCR-1 리스트/이미지 선택 -> `SCR-1.1 모달` 오픈
3. SCR-2 리스트 선택 -> `SCR-2.1 모달` 오픈
4. 모든 화면에서 벨 아이콘 클릭 -> `SCR-opt` 슬라이드 오픈

---

## 8. API-UI 매핑 (구현 기준)
1. `GET /dashboard/replenishment-summary` -> SCR-1 Overview 카드
2. `GET /dashboard/replenishment-items` -> SCR-1 리스트
3. `GET /dashboard/shelf-image` -> SCR-1 선반 이미지 + bbox 데이터
4. `GET /dashboard/order-summary` -> SCR-2 요약 카드
5. `GET /dashboard/order-items` -> SCR-2 리스트
6. `GET /dashboard/order-item/{sku}` -> SCR-2.1 모달 상세
7. `GET /notifications` -> SCR-opt 알림 리스트
8. `POST /tasks/replenishment/{sku}/complete` -> SCR-1 보충 완료
9. `POST /tasks/order/{sku}/complete` -> SCR-2 발주 완료

---

## 9. 비고
1. 디자인 시안 상 중복 SKU는 샘플 데이터 복제이므로 실제 구현에서는 단일 SKU 1행 원칙을 강제한다.
2. 리스트 고정 높이 + 내부 스크롤은 성능/가독성 확보를 위한 필수 요구사항이다.
